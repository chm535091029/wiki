# 板块 03：服务与接口

**核心思想**：接口层的核心是语义正确与边界清晰。需要建立的判断力是：状态码是否用对、写操作是否幂等、鉴权方案是否与场景匹配。

上级索引：[AI 应用后端知识地图](./00-overview.md)

## 一、HTTP 语义

**方法语义**，重点在幂等性：

| 方法 | 语义 | 幂等 | 说明 |
|------|------|------|------|
| GET | 读取 | 是 | 不应产生任何副作用 |
| POST | 创建 | 否 | 重复调用会创建多条 |
| PUT | 全量替换 | 是 | 重复调用结果一致 |
| PATCH | 局部更新 | 否 | 取决于实现 |
| DELETE | 删除 | 是 | 重复调用结果一致 |

**状态码只需要记住几组**：

| 码段 | 含义 | 常见用法 |
|------|------|----------|
| 2xx | 成功 | 200 常规、201 已创建、202 已接受（异步任务） |
| 3xx | 重定向 | 301 永久、302 临时、304 未修改 |
| 4xx | 客户端错误 | 400 参数错、401 未认证、403 无权限、404 不存在、409 冲突、429 限流 |
| 5xx | 服务端错误 | 500 内部错误、502 上游异常、503 不可用、504 上游超时 |

两个高频误区：把认证失败写成 403（应为 401），把所有错误都返回 200 再用响应体里的字段标识错误。后者会让监控、重试、网关全部失效。

**幂等键**：写操作若需支持重试，应由客户端携带一个唯一请求 ID，服务端记录该 ID 与结果，重复请求直接返回首次结果。这是支付、扣费、创建资源的标准做法。

**分页**：偏移分页（`offset` / `limit`）简单但在大偏移量时性能差；游标分页（基于排序字段值）性能稳定，适合数据量大或持续写入的场景。列表接口必须有上限，禁止无参数返回全量。

## 二、鉴权方案

| 方案 | 状态保存在哪 | 能否主动失效 | 适用 |
|------|--------------|--------------|------|
| Session | 服务端（内存或 Redis） | 能 | 传统 Web，需要登出即失效 |
| JWT | 客户端令牌自包含 | 不能，需配黑名单 | 无状态服务、跨服务传递 |
| API Key | 服务端（数据库） | 能 | 服务间调用、第三方接入 |
| OAuth2 | 授权服务器 | 能 | 第三方登录、代用户访问 |

**JWT 的关键限制**：签发后到过期前一直有效，服务端无法单方面作废。因此不能用于需要立即吊销的场景。常见补救是维护黑名单，但那等于又把状态放回了服务端，失去了无状态的意义。

**API Key 的存储**：数据库里不应存明文 key，应存哈希值，只在创建时展示一次。key 要能设置状态与配额，支持单独禁用。

**RBAC**：角色绑定权限，用户绑定角色。判断代码是否实现正确，看鉴权是校验"角色"还是校验"权限点"。前者在角色增多后会失控。

**分布式鉴权的三个前置条件**：多节点部署时，会话密钥必须各节点一致，否则登录状态在不同节点间不一致；代理层来源必须可信配置，否则 IP 与协议头可被伪造；Cookie 的安全标志需在 HTTPS 下开启。

## 三、边界与代理

**CORS**：跨域报错的根因是浏览器的同源策略，不是服务端拒绝请求。服务端通过响应头声明允许的来源。生产环境不要使用通配的来源，应配置白名单。

**反向代理的职责**：终止 TLS、转发请求、设置真实客户端 IP 的请求头、处理流式与 WebSocket 的协议升级、限流与超时。流式接口经代理时容易出问题，需确认代理未开启响应缓冲。

## 四、网关的典型职责

New API 这类网关把下面这些职责从业务服务中收拢到一层：

| 职责 | 说明 |
|------|------|
| 统一入口 | 把上游多家服务商的接口收敛成一套规范 |
| 协议转换 | 不同上游的请求与响应格式互相映射 |
| 路由选择 | 按模型、分组、权重选择上游渠道 |
| 配额与计费 | 按用量扣减额度，支持不同计费模式 |
| 密钥托管 | 上游密钥集中加密存储，业务侧不见明文 |
| 限流与重试 | 在网关层统一处理 |

## 五、New API 中的落点

| 概念 | 落点 |
|------|------|
| 分层架构 | Router → Controller → Service → Model 四层，路由在 `router/`，业务在 `controller/` 与 `service/` |
| 中间件链 | Gin 中间件处理鉴权、限流、国际化，限流在 `middleware/rate-limit.go` |
| API Key 方案 | TOKEN 表存 key 与状态、配额，是标准的 API Key 体系 |
| 令牌分组与限制 | 令牌可绑定分组与可用模型范围，属于细粒度授权 |
| 多种登录方式 | 支持 OAuth2 / OIDC / Telegram 等，登录态由 Session 承载 |
| 会话密钥 | `SESSION_SECRET`，多机部署必须各节点一致 |
| 代理来源 | `TRUSTED_PROXIES` 配置可信反向代理的 IP 或网段 |
| 密钥加密 | `CRYPTO_SECRET` 加密渠道密钥，多节点共享 Redis 时必须一致 |
| 协议转换 | `relay/` 目录下的各家适配器，处理 OpenAI 与 Claude、Gemini 等格式互转 |
| 计费模式 | 按次计费、缓存计费（提示缓存倍率）等多种模式 |

`relay/` 这一层的设计值得注意：它把"协议差异"收敛在适配器里，新增上游只是新增一个适配器，不改动主流程。这是接口设计里"变化点隔离"的标准做法。

## 六、典型误写与修正

### 所有结果都返回 200

误写方向：把错误塞进响应体字段。这样监控统计不到失败，网关无法按状态码重试，客户端拦截器也失效。

```python
@app.post("/login")
async def login(body: LoginIn):
    user = await repo.find(body.username)
    if not user:
        return JSONResponse({"code": 1, "msg": "用户名或密码错误"})   # HTTP 200
    return JSONResponse({"code": 0, "data": issue_token(user)})
```

修正：状态码表达结果，响应体只承载数据。

```python
@app.post("/login")
async def login(body: LoginIn):
    user = await repo.find(body.username)
    if not user or not verify(body.password, user.password_hash):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    return {"token": issue_token(user)}
```

对应关系要记牢：未认证用 401，已认证但无权限用 403，参数错误用 400，资源不存在用 404，状态冲突用 409，限流用 429。

### API Key 明文入库

误写方向：数据库泄露即等同于所有 key 泄露。

```python
await db.execute("insert into tokens (key) values ($1)", raw_key)
```

修正：只存哈希，明文仅在创建时返回一次。

```python
key_hash = hashlib.sha256(raw_key.encode()).hexdigest()
await db.execute("insert into tokens (key_hash) values ($1)", key_hash)
# 明文一次性返回给用户，服务端不再保留
```

### 写接口没有幂等键却允许重试

误写方向：网关或客户端一次重试，用户被扣两次钱、下两次单。

```python
@app.post("/orders")
async def create(body: OrderIn):
    return await db.insert("orders", body)          # 重试即重复创建
```

修正：客户端携带幂等键，服务端记录首次结果，重复请求直接返回。

```python
@app.post("/orders")
async def create(body: OrderIn, idem_key: str = Header(...)):
    existed = await repo.get_by_idem_key(idem_key)
    if existed:
        return existed                              # 返回首次结果，不重复写入
    return await db.insert("orders", body, idem_key=idem_key)
```

## 七、审查红灯信号

- 所有错误都返回 200，用响应体字段标识失败。
- 认证失败返回 403 而非 401。
- 写接口没有幂等键，却配置了自动重试。
- 列表接口没有分页或没有上限。
- 数据库存 API Key 明文。
- CORS 允许任意来源并同时允许携带凭证。
- 鉴权校验角色而非权限点。
- 多节点部署但未设置统一的会话密钥。
- 流式接口经过反向代理但未确认缓冲已关闭。

## 八、判断阈值

- 能判断一个失败响应该用 4xx 还是 5xx，该用哪个具体码。
- 能说明所选鉴权方案能否主动失效，是否满足业务需求。
- 能判断一个写接口在重试场景下是否会产生重复数据。
- 能说清网关层与业务层各自应承担哪些职责。
