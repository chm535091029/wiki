4 FocusChain（进度锚定）

任务进度从模型短期记忆→持久化状态机

  • 清单存储在磁盘文件，支持持久化、外部可编辑、双向同步、文件监听
  • task_progress 设计为所有工具调用的可选参数
  • 模型可跳过字段（不影响工具执行），但 Harness 每隔 N 轮强制提醒
  • Harness 解析 task_progress 后：写文件到磁盘、通知 UI 更新、重置计数器、触发 telemetry

CygCode FocusChain

文件级持久化 — 模型不依赖自身记忆

  • 清单存储在磁盘文件中，任务中断后重启仍能看到进度
  • 外部可编辑：用户勾掉某项 → 系统感知 → 下一轮提示
  • 双向同步：UI ↔ 磁盘 ↔ LLM 上下文实时一致
  • 文件监听：避免编辑过程中的假阳性更新
  • task_progress 参数：可跳过但会被提醒
  • Interval 门控：默认 6 轮才强制校验，减少每轮开销
  • 进度注入时机：PLAN 弱提示、切 ACT 强要求、6 轮督促、第 1 轮建议、多轮强催
  • 结果标注：完成项后必须标注结果/发现

CC TodoWrite + Task V2 4 工具+1存储

V1 TodoWrite (deferred) + V2 四工具系统 (file-persisted)

  • V1 TodoWrite：shouldDefer=true，patch appState.todos[agentId]，自动清理
  • V2 四工具：TaskCreate / TaskGet / TaskList / TaskUpdate（4个独立工具，均 shouldDefer=true）
  • V2 存储：~/.cline/tasks/{taskListId}/ 下独立 JSON 文件 + .lock + .highwatermark
  • V2 TaskUpdate 6 操作：标记状态/完成(含验证nudge)/删除(硬unlink)/修改描述/设依赖/分配owner
  • 提醒周期：10 轮未使用工具 + 10 轮未提醒 → 注入 isMeta 元消息
  • V1 状态：AppStateStore.todos[agentId]（不持久化，从 transcript 恢复）
  • V2 状态：独立 JSON 文件（持久化，不依赖 transcript）
  • 任务依赖：V2 支持双向依赖（blocks/blockedBy），TaskList 自动过滤已完成 blocker
  • Desktop 集成：同时监听 TodoWrite（V1）和 TaskCreate/TaskUpdate（V2）tool_use
  • 按 agent 隔离：每个 subagent 有独立的 todo/task 列表
V2 完整生命周期： TaskCreate("用户注册")→[in_progress]→TaskUpdate(id:2,addBlockedBy:["1"])→[completed] → TaskList→自动流转至下一个→TaskUpdate(id:2,status:"in_progress") 删除: TaskUpdate({id:4, status:"deleted"}) ← unlink 文件+清除依赖引用 修改: TaskUpdate({id:3, subject:"新描述"}) ← 增量字段更新

核心差异

FocusChain 磁盘文件 + 文件监听 + 用户可编辑 + task_progress 参数（所有工具调用可选传入） → 更强调「用户外部干预」和「文件级持久化」 → Interval 门控减少每轮 token 开销 → 结果标注确保每步有产出记录 TodoWrite/Task V2 appState.todos[agentId] + V2 文件持久化 + Plan Mode 封闭状态机 → 更强调「状态机封闭性」和「自驱验证闭环」 → V1/V2 两套并行，通过 feature flag 切换 → 提醒周期（10+10 轮）= 比 FocusChain 的默认 6 轮更宽松 共同点：跨 iteration 持久、可被强制提醒、不依赖模型记忆
