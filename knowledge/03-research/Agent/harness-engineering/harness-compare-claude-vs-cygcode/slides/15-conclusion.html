核心结论：Harness 工程的 7 条通用原则

CygCode 角度的洞察
  • 每轮重建：12 Section 完整重建，规则改动立即可见
  • Variant 系统：按模型能力适配措辞力度（generic/next-gen/xs）
  • FocusChain 文件级持久化：用户可编辑、双向同步、文件监听
  • task_progress 可跳过但会被提醒：软约束 + 硬催促结合
  • 软硬约束多层冗余：同一约束在 System Prompt + Tool Schema + FocusChain + Rules 多处独立表达
Claude Code 角度的洞察
  • byte-stable 缓存：静态/动态分离降低 token 消耗
  • 27 个 Hook 事件：规则可编程化的天花板
  • Subagent 规则分舱：多 Agent 协作时规则随委派分割
  • Compact 不丢约束：压缩后自动触发 L1-L6 全部再注入
  • Nudge 动态提醒：基于「刚发生的事件」而非固定模板
两套体系并非竞争，而是投影在不同代码库上的同一方法论

根本哲学完全一致：把 LLM 当作无状态、健忘、易分心的协作者，所有约束每轮重新注入，形成对状态的外部控制。
差异主要在分层粒度（4+4 vs 8）、缓存策略、Subagent 支持和 Hooks 丰富度上。
