投影 vs 替换 vs 压缩 — 三种收缩手段

📽 投影 Projection

像 Git stash：REPL 完整保留，API 只见短 ID

REPL 保留 · API 不发
✅ 可逆

REPL 数据✅ 完整保留
磁盘备份❌ 不需要
发给 API❌ 短 ID [id:xxx]
下轮恢复✅ 展开 ID → 全量
⏱ 触发时机：
• Snip：HISTORY_SNIP 开启时，每轮检查可投影消息 → 替换为 [id:xxx]
• Collapse：上下文 >90%/95%，单大 tool 折叠为 [id:foldN]
🔁 如何复原：
模型需要查看时，通过短 ID 回查 REPL state → 提取原文 → 重新注入对话。
因为 REPL 始终持有完整数据，投影是完全可逆的。

🗃 替换 Replacement

像文件缩略图：原文件存磁盘，对话只看预览

永久改 state.messages
⚠ 对话不可逆，数据不丢失

REPL 数据🔄 preview 字符串
磁盘备份✅ 完整保存
发给 API✅ 2KB preview
下次再发✅ byte-identical 不重算
⏱ 触发时机：
• 单 msg tool_result > 50K 字符 → 写入磁盘 + 生成 2KB preview + 附加路径提示
• 同一结果再遇到 → 直接返回缓存中的 byte-identical preview
🔁 如何复原：
state.messages 已被 preview 替换（不可逆）。但原始数据在磁盘上，且 preview 携带路径提示（path hint）。模型需要时可通过 Read 工具重新读取文件，获取完整内容。

📄 压缩 Compression

像会议纪要：保留要点，丢掉逐字稿

splice 删除 + summary
⚠ 不可逆，但 L7 保证规则不丢

REPL 数据❌ splice 删除
磁盘备份🔄 session log 可查
发给 API✅ summary (~5K)
下轮恢复❌ 需手动从 log 恢复
⏱ 触发时机：
• autoCompact：token ≥ effectiveWindow − 13K → fork agent 生成 summary → splice 替换
• reactiveCompact：API 返回 413（prompt too long）→ 用户不知情下自动重试并压缩
🔁 如何复原：
对话原文不可恢复（splice 已删除）。
但 L7「压缩后规则再激活」 在 boundary 后立即：重新 prepend Rules、重新计算附件/nudge、重新触发 hook、保持 permission mode 和 todo 状态——规则永远在场，只丢了历史细节。

5 层 tool_result 预算 + Read 豁免

预算层触发条件效果示例
1. 单工具上限maxResultSizeChars 声明截断/返回 partialRead=Infinity（豁免）
2. 每 msg budget该轮 tool_result > 50K 字符持久化 + preview + 路径提示80KB grep → preview
3. Time-based MClastAssistant > 60 min清空为 "[Old tool result cleared]"午休后回来已清
4. Cached MCGrowthBook 阈值API 层删旧 tool（保留 cache prefix）服务端自动处理
5. Context Collapse上下文 > 90%/95%单 tool 折叠为短 ID80KB auth.ts → [id:fold1]

Read 豁免防止死循环：Read 工具 maxResultSizeChars=Infinity → 不被 budget 压缩。否则「压缩→Read 磁盘 txt→再压缩→再 Read」死循环。
fileStateCache (LRU 100/25MB)：同一文件再读 → 返回 "Already read" 不重复注入 80KB。
Cache 策略：替换 byte-identical（破坏 cache prefix = token 浪费）→ 静态/动态分离 → Tools schema session-stable base + overlay
