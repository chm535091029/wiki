双层截断防御体系

Handler 层（工具侧）

在 tool_result 返回 messages 之前执行

  • read_file: 默认 1000 行，400KB 字节上限，20MB 硬限制
  • list_files: 最多 200 个文件
  • MCP 工具/资源: 400KB 上限
  • Excel: 每 Sheet 50000 行
  • Subagent output: 仅 .trim() 透传 excerpt() 已移除
例：Read(src/api.ts) 输出 1200 行 → Handler 截断前 1000 行 + "[200 行被截断]"

ContextManager 层（消息侧）

在完整 messages 上执行统一去重+压缩

  • 找重复的 file read / write / @mention → 只保留最后一次
  • 旧版本替换为 [NOTE: 历史文件状态。请使用新消息查看]
  • 如果节省 < 30%，仍触发截断
  • 截断后插入 Truncation Notice 显式告知 LLM
  • 修复 tool_use/tool_result 配对错乱
例：同一文件 Read 了 3 次 → 保留最新一次，前两次替换为 [NOTE]

Subagent 输出截断移除 & 规则注入 2026-06-17

excerpt() 已移除： 原截断上限 1200 字符 → 仅保留 `.trim()` 透传 excerpt() 函数作为死代码仍保留，但 summary 组装中不再调用 主 agent 现在能看到 subagent 的完整输出 保护措施仍然有效：read_file/MCP 400KB、read_file 1000行、list_files 200文件 Subagent 用户规则自动注入： Subagent 的 system prompt 同样通过 PromptRegistry 构建 componentOrder 中包含 USER_INSTRUCTIONS_SECTION 用户规则（.clinerules / .cursorrules / .agents/AGENT.md / .clineignore） 自动注入到 subagent 的 system prompt 中 无 isSubagentRun 过滤 ↔ 团队规范延伸到 subagent

★ 5 个 Hook 点 — 项目级外部干预通道

Hook 事件一览

TaskStart → 任务开始时注入 context UserPromptSubmit → 每次用户输入提交时注入 TaskResume → 任务恢复时注入 context TaskCancel → 可阻止 agent 取消任务 PreCompact → 可阻止自动压缩

返回值：contextModification → 以 标签注入 userContent

实现方式：command（shell 脚本）/ http（webhook）/ callback（进程内）

与 CC 的对比

  • 侧重任务生命周期（开始/提交/恢复/取消/压缩前）
  • 返回值 contextModification 注入 userContent
  • TaskCancel/PreCompact 可返回 continue:false 阻止操作

  • PreToolUse 可改写参数/决定 allow/deny/ask
  • PostToolUse 可注入 context + 阻止继续
  • SubagentStart/Stop 可隔离子代理
  • deny > hook allow，防御纵深

四种截断策略详解 — 何时触发？每条什么意思？

触发条件：上轮 API 调用后 token 消耗超过 context window 可用空间 例如 128K window → 实际消耗 > 98K（预留 30K）→ 截断触发 ↓ Step 1：先去重 找重复的 read_file / write_to_file / @mention - 同一文件出现多次 → 只保留最后一次完整内容 - 历史版本替换为 [NOTE: 历史文件状态。请使用新消息查看] - 如果去重节省 ≥ 30% 的 space → 仅去重就够，跳过截断 - 如果去重节省 < 30% → 去重后仍要截断 ↓ Step 2：按策略截断 half → 删除一半 user-assistant pair quarter → 删除3/4 user-assistant pair lastTwo → 只保留最近两轮 user-assistant pair none → 不删除任何 pair，只做去重 ↓ Step 3：替换首条 user + 插入 Notice 替换首条 user 消息为简洁提示 在第一条 assistant 消息前插入截断通知 ↓ Step 4：修复配对 检查 tool_use ↔ tool_result 是否成对

Buffer 预留计算

64K context → 预留 27K (可用 37K) 128K → 预留 30K (可用 98K) 200K → 预留 40K (可用 160K) 预留空间用于：system prompt + 即将生成的 LLM 输出

Auto-Condense（next-gen 模型默认）

shouldCompact = isNextGenModel && (上轮 token ≥ 阈值) → 尝试 file read 去重 ├─ 节省 ≥ 30% → skip auto-compact，去重就够了 └─ 节省 < 30% → 追加 指令 → LLM 调用 summarize_task 工具生成摘要 → 摘要注入下一轮作为 user message → conversationHistoryDeletedRange += 2
