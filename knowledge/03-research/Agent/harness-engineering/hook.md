# Hook 机制详解

## 什么是 Hook

Hook 的直译是**钩子**，它把一个事件和一个确定性的脚本联系在一起，在对应的时间点触发预定义的脚本执行。

## 生命周期事件

在 Cloud 的整个文本对话中会有一系列的时间点（生命周期事件），目前支持的超过 20 个：

| 事件类型 | 说明 |
|---------|------|
| Session Start | 对话开始 |
| User Submit | 用户提交提示词 |
| Pre Tool Use | 工具调用前 |
| Post Tool Use | 工具调用后 |
| On Stop | 对话结束时 |

## Hook 的工作机制

### 触发机制

在每一个对应的生命周期事件中都可以插入一个脚本：

```
┌─────────────────────────────────────────────────────┐
│                  生命周期事件                         │
│                                                     │
│  Session Start ──→ Pre Tool ──→ Post Tool ──→ Stop │
│      │              │             │                │
│      ▼              ▼             ▼                │
│   [Hook 1]      [Hook 2]     [Hook 3]             │
│   脚本执行       脚本执行      脚本执行              │
└─────────────────────────────────────────────────────┘
```

### 退出码控制

Hook 脚本执行完成后会返回退出码，告知 Cloud 下一步应该做什么：

| 退出码 | 含义 | 后续行为 |
|-------|------|---------|
| 0 | Hook 执行完成，认为 AI 做的事情正确 | 继续执行 |
| 2 | Hook 执行完成，认为 AI 做的事情质量不过关 | AI 获取错误信息，自动调整方案并重试 |

**核心思想**：确定性并不是通过告诉 AI"请你不要犯错"的方式去拦截它，而是有一个确定的脚本。每次 AI 做完事情之后都会运行这个脚本，用脚本告诉 AI 他做的事情是对的还是错的。

## 项目实例

### Hook 定义结构

```yaml
hooks:
  - name: pre_tool_use
    match: "**"
    command: "./cloud-hooks/pre-tool-use.sh"
  
  - name: post_tool_use
    match: "**"
    command: "./cloud-hooks/post-tool-use.sh"
```

### 常用 Hook 场景

#### 1. Session Start 时
- 检查有没有未解决的 QA 问题
- AI 一上来就知道应该继续做什么

#### 2. 工具调用前 (Pre Tool Use)
- 检查是否使用了共享组件
- 检查是否在写迁移文件
- 进行权限鉴别

#### 3. 工具调用后 (Post Tool Use)
- 压缩工具输出，节省上下文
- 自动 get 新的文件
- 格式检验，产出是否符合要求

#### 4. 失败时
- 让 AI 自动记录失败原因
- 写入 reflection 文件供后续读取
- AI 可以自我学习什么东西应该怎么用

#### 5. Stop 时
- 用 TS 编译 + 测试做验收标准检查
- 触发 Codex 进行交叉审阅

## Conditional Hook

支持条件拦截，只拦截特定类型的操作：

```yaml
- name: pre_tool_use
  if: "tool.name == 'Edit' || tool.name == 'Batch'"
  command: "./cloud-hooks/pre-tool-edit.sh"
```

通过定义 `if` 条件，可以只在 AI 尝试执行特定操作时才进入 Hook，提升效率。

## 总结

Hook 的核心价值：

1. **确定性**：不依赖 AI 的理解能力，通过代码强制执行
2. **拦截前**：可以做权限鉴别、共享组件检查
3. **拦截后**：可以做格式校验、输出压缩
4. **失败时**：可以写反思，实现 AI 自我学习
5. **结束时**：可以做检查验收

**本质**：在对应的时间点确定性起一个脚本，帮助限制 AI 的能力和犯错空间。
