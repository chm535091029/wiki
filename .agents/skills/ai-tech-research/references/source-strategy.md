# 信息源检索与交叉验证策略

## 官方一手来源（优先级最高）

- **arXiv**：`<技术名> arxiv` 或 `<技术名> paper`。先读 `/abs/<id>` 摘要，再读 `/html/<id>v1` 正文（含公式、表格、架构描述）。
- **GitHub 官方仓库**：`<vendor>/<repo>`，重点 README、训练/评估脚本、开源 checkpoint、`NOTICE`/使用须知、issue 中的已知问题。
- **官方博客/发布页**：厂商技术博客、模型卡（model card）、发布说明。

## 社区解读（辅助理解 + 交叉验证）

- 中文：知乎、CSDN、少数派、厂商技术社区专栏。
- 英文：Medium、dev.to、厂商技术博客转载。
- 用途：把论文中的公式/机制翻译成直觉解释；发现论文未明说的工程细节；补充落地经验。

## 交叉验证规则

1. 性能数字（吞吐、接受长度、延迟、准确率）至少两个来源一致；冲突时以官方论文/仓库为准。
2. 标注"名义值 vs 实测值""严格 SLA 下退化"等口径，避免误读。
3. 文档中所有关键数据可追溯至具体来源（论文表号、仓库文件、博客段落）。
4. 若某项技术刚发布、社区解读稀少，应明确说明"社区验证不足"，不要臆造结论。

## 工具

- `WebSearch`：多关键词组覆盖中英文与多平台（每次可带多组 `query_keyword_groups`）。
- `WebFetch`：抓取论文摘要页、HTML 正文、仓库 README 提取细节与具体数值。
